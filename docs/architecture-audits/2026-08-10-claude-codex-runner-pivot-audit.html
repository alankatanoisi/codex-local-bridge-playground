1. Executive summary and recommended pivot

The Codex repository has a sound native Responses vertical slice. The pivot is not to replace it with Claude code; it is to surround it with the stronger provider-independent safety, state, recovery, and orchestration contracts that evolved later in the Claude playground.

Decision: keep native message, reasoning, function_call, and function_call_output items end to end. Stop a file-by-file port. Converge at the authority, tool execution, private state, recovery, output, budget, and worker interfaces.

The five-part pivot

  1. Preserve Codex-native work: Items, SSE assembly, call/result pairing, schema v2, fixtures, goldens, fence tests, and Stage 7 pricing.
  2. Define a provider-neutral harness contract: immutable authority, capability visibility, path ownership, trust, redaction, private persistence, recovery, outputs, budgets, and workers.
  3. Repair shared state first: provider/lane namespaces, strict schema selection, private modes, and a non-destructive legacy-artifact plan.
  4. Build Responses-native context projection: preserve reasoning and call/result units; do not reuse Anthropic content-block compaction.
  5. Choose the transport boundary: prefer documented Codex app-server automation; otherwise explicitly accept the direct endpoint as experimental.
Recommended first owner decision: choose app-server versus experimental direct backend. Do not spend the pending live-canary budget until that choice defines what the proof is supposed to prove.

4. Current architecture of each location

Claude playground

A native Anthropic runner, a Claude-specific local OAuth transport shim, and a separate Starlark orchestration host. The runner now has an immutable authority ceiling, capability groups, private serializers, strict recovery, rebuilt context projection, and bounded child leases. Agent/profile runtime concepts are retired. Bundle C records a bounded 25-trial Starlark planner evaluation with corrected scorer logic. The final head also adds measured cheap-tier escalation, a deterministic zero-cost second worker provider, and validated host-JSON planning for fully determined fan-out. This strengthens the separate control-plane evidence without making it a native Runner integration.

Codex playground

A native Responses conversation and SSE core surrounded by an older inherited harness. It keeps native Items and provider-tagged schema v2, but lacks the latest authority, private-state, recovery, capability-group, and context controls. Profiles and file agents remain active.

~/.bridge-runner

A shared sensitive state/control root—not source code. It holds sessions, logs, traces, archives, campaigns, worktrees, trust, and user skills from multiple versions and provider lanes. The root is private, but many historical/current artifacts have mixed 0600/0644 files and 0700/0755 directories.

Canonical Claude bridge

Historical boundary archaeology: local server, credential discovery, proxy, fingerprinting, and old multi-route/API-key behavior. Its tests pass its old contract, but OpenAI-compatible routes and credential fallbacks are obsolete for both active native lanes.

9. Security, permissions, credentials, and trust

Provider-independent invariants

  1. Startup authority can only narrow.
  2. Plan mode creates no effects.
  3. Shell is explicit unsandboxed host authority.
  4. dont-ask never reveals hidden authority.
  5. Permission and execution share realpath rules.
  1. Sensitive paths/env remain hard-denied.
  2. Children inherit only subsets and leases.
  3. Every output/persistence boundary scrubs.
  4. Sensitive state is private by explicit mode.
  5. Transport success is not semantic success.
Current Codex gaps: no immutable ceiling, default-mode state writers, older ledger cursor rules, active profiles, and no central circular-safe redaction boundary. Individual safety checks exist; the concern is missing system-level monotonicity and sink consistency.

Provider support evidence

OpenAI documents workspace access tokens for Codex CLI/app-server trusted automation and distinguishes them from Platform API keys. The environment-only token source is narrow, but those documents do not establish this custom direct backend POST as a supported public integration. See Codex access tokens, authentication/environment, and Responses migration.

Anthropic documents Claude Code OAuth automation while also distinguishing subscription OAuth/native-app use from developer product/service API authentication. The local fingerprint-replay bridge remains personal research, not provider approval. See Claude Code authentication, legal/compliance, and API authentication.

Claude's one current known test gap is HS-01, a case-variant sensitive-filename deny case. It remains an explicit TODO pinned by suite-integrity tests; the correct result is 993 passed plus one TODO.

10. Context, compaction, state, persistence, recovery, and orchestration

Native conversation rule

Responses uses Items; Anthropic uses Messages/content blocks. Shared code can own budgets, integrity outcomes, and projection interfaces, but each provider adapter must own its concrete sequence. OpenAI's guidance requires carrying reasoning and related function-call/output items when context is managed; Anthropic requires its own tool-use/result ordering. See reasoning context, function calling, and Anthropic tool handling.

Claude context engine

Raw history and request projection are separated; instruction identity, context epoch, deterministic policy, and an Anthropic message contract are explicit. The architecture idea is portable; the content-block implementation is not.

Codex context gap

Native history deliberately bypasses the inherited Anthropic compactor. That prevents corruption, but means long-session compaction and “compact” flags do not reclaim native context.

Cross-provider state defect

~/.bridge-runner/sessions/
  ses_*.state.json     # Claude v1 messages[] OR Codex v2 provider=codex/items[]
  ses_*.ledger.jsonl
  ses_*.ledger.jsonl.cursor.json

Claude's selector chooses the newest state file by modification time without provider/schema filtering. Its loader accepts the Codex object and then the run path reads messages.length. Codex rejects a Claude state cleanly, but Codex --continue selects a transcript that its run loop rejects.

Names are illustrative. Required properties are provider/lane identity, strict schema validation, private modes, atomic indexes, compatible latest selection, and no automatic legacy deletion/rewrite.

Recovery and orchestration

Claude now requires exact cursor/file-size concordance, handles torn tails, writes privately, and reconciles intent/result events. Codex's older cursor can accept unseen appended bytes and uses ordinary modes. Worker parity likewise requires narrowed authority, token/dollar/wall leases, cancellation, and safe environment—not copied profile names.

The Starlark host is promising above the loop: deterministic evaluator, validated descriptors, durable campaign budgets, semantic synthesis, synthesis-only resume, measured planner escalation, and a second deterministic provider behind the same registry contract. Its host-JSON cheap path skips unnecessary generated code but not descriptor validation. Keep it separate and add a Codex adapter only after the single-run gates.

The concurrently landed Bundle C aggregate reports five planner models × five repetitions, 271 upstream calls, and $6.2881 settled under prior owner authorization. It records zero authority-field attempts, zero permanent-fault retries, 25/25 complete traces, and three scorer defects caught before corrected aggregates were published. Its model ranking is directional (n=5, one fixture/day/fixed worker); its stronger architecture lessons are concise descriptors, validated scorers, and keeping evaluation/orchestration separate from the runner core.

The later R9/R13/R14c commits add source-, test-, and offline-runtime evidence only: no new live provider campaign was run. They prove a provider seam with a deterministic adapter, recorded cheap-tier escalation, and a zero-model-call fully determined pipeline while preserving host-owned routing and validation.

15. Risks of over-porting Claude-specific architecture

Do not copy the data plane

Anthropic compaction, thinking blocks, tool-result adjacency, cache markers, model controls, and session payloads can corrupt or flatten native Responses semantics.

Do not copy transport/auth

OAuth discovery, fingerprints, interception, local server routes, and canonical API-key fallbacks are Claude-specific and policy-sensitive.

Do not merge orchestration early

Adding Starlark before single-run transport/state/authority stabilization multiplies uncertainty and budget risk.

Do not turn state into code

~/.bridge-runner should hold private, versioned data—not unversioned shared source modules.

Restate every candidate invariant without provider vocabulary, implement it through the native adapter, and prove it with provider-specific plus cross-provider tests.

20. Beginner-friendly meaning and next step

Picture the runner as a workshop: a foreman decides what is allowed, a translator speaks the model's language, a delivery driver reaches the provider, and a filing room stores sessions and recovery records.

Foreman

Trust, read/write/shell/network authority, workers, and budgets. The newer Claude workshop has the stronger foreman.

Translator

Claude Messages and Codex Responses Items are different languages. Codex already has a good native translator.

Driver

Claude uses the local OAuth bridge. Codex should choose a documented app-server driver or accept an experimental direct one.

Filing room

Both runners currently put incompatible session documents in the same drawer. Separate and label the drawers first.

Do not replace the Codex translator. Give it the stronger common foreman, private provider-owned filing drawers, honest recovery, and its own safe way to shorten long Responses conversations.
